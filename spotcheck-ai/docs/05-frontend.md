# 05. フロントエンド仕様

Next.js (App Router) + TypeScript + Tailwind CSS。
GUI草案の画面①〜⑩をすべて実装する。**画面番号は草案に対応しているため変更しない。**

`tailwind.config.ts` に定義する。

## 2. デモユーザー切替（D-06）

- トップ `/` にロール選択画面を置く。`GET /api/users/demo` の一覧からユーザーを選ぶ。
- 選択したIDを `localStorage` に保持し、`lib/api/client.ts` が全リクエストに `X-Demo-User-Id` を自動付与する。
- ヘッダー右上に現在のユーザー名を表示し、タップで切替できるようにする（**デモ中にクライアント⇔ワーカーを即座に往復するため必須**）。

## 3. 画面仕様

### 画面① 依頼作成 `/client/tasks/new`

**構成（上から）**
1. **地図で地点を指定** — Google Maps。タップでピンを配置し `locationLat/Lng` を更新。初期中心は環境変数の既定座標。逆ジオコーディングで住所を取得し下部に表示。
2. **日時を指定** — 撮影希望日時（`scheduledAt`）と提出期限（`deadlineAt`）。日付＋時刻ピッカー。
3. **撮影人数** — 1〜10のステッパー。
4. **報酬** — 円単位の数値入力。100〜100000。
5. **詳細メッセージ入力** — textarea。10〜1000文字、文字数カウンタ付き。プレースホルダ:「周辺の工事状況や交通状況を確認してください。」
6. **参考画像アップロード** — 最大3枚。サムネイル＋「＋」ボタン。草案①の見た目に合わせる。
7. **「依頼内容を確認」ボタン** — 全幅の青ボタン。

**バリデーション（送信前）**
- 未入力項目があればボタンを無効化し、該当フィールド下に赤字でメッセージ表示。
- 送信中はボタンをローディング状態にする。**AI審査が同期実行されるため最大30秒かかる旨**を「AIが依頼内容を審査しています…」というテキストで表示する。

### 画面② AIリクエスト審査 `/client/tasks/new/review`

`POST /api/tasks` のレスポンスを受けて表示する。草案②に対応。

**構成**
- ヘッダー:「AIリクエスト審査（OrcaAI）」
- **スコアリング** — `reviewScore` を `85 / 100` の形式で大きく表示。
- **チェック項目4行** — 内容の妥当性チェック / リスクチェック / 重複・類似チェック（＋スコアリング）。各行の右に ✓（emerald）または ✗（red）アイコン。
- 結果パネル（`decision` により分岐）:

| decision | 表示 |
|---|---|
| `approved` | 緑パネル「スコア高 → 依頼を公開」。3秒後に画面③へ自動遷移（「今すぐ確認」ボタンも置く） |
| `needs_info` | 赤パネル「スコア低 → 内容補足を依頼」。`missingInfo` を箇条書き表示し、**その場で詳細メッセージを編集できるtextareaと「再審査する」ボタン**を出す（`POST /api/tasks/{id}/resubmit`） |
| `rejected` | 赤パネル。`rejectionReason` を表示。編集フォームは出さず、「新しい依頼を作成」ボタンのみ |

> `rejected` のときに再提出フォームを出さないのは、**却下された依頼の言い換えによる回避を促さないため**。

### 画面③ 依頼公開・進行状況 `/client/tasks/[taskId]`

**構成**
- ステータスバッジ（例:「募集中」）
- **依頼内容の要約** — `reviewSummary`
- 位置情報 / 期限 / 報酬 / 募集人数（アイコン付きの行）
- **進行状況タイムライン** — `timeline` 配列を縦のステッパーで表示。`done` は青丸＋日時、`current` は青枠、`pending` は灰丸。
- N人受注時は「受注状況 2 / 3人」を表示する。
- `completed` または合格提出が1件以上あるとき、「結果を見る」ボタン（→画面⑨）を表示する。
- **10秒ごとにポーリング**してタイムラインを更新する。

---

### 画面④ 依頼一覧 / 地図 `/worker/tasks`

草案④に対応。**「地図」「リスト」のタブ切替**を上部に置く。

- 起動時に `navigator.geolocation.getCurrentPosition()` で現在地を取得し、`GET /api/tasks/nearby` を呼ぶ。
  - 位置情報が拒否された場合は既定座標にフォールバックし、「現在地を取得できませんでした」を表示する。
- **地図タブ** — 現在地を青丸、タスクを緑ピンで表示。ピンをタップすると下部にカード（タイトル・報酬・距離・期限・「詳細を見る」）をスライド表示。
- **リストタブ** — 同じ内容をカードの縦並びで表示。並び替え（距離順 / 報酬順 / 期限順）のセレクトを置く。
- 各カードに `remainingSlots` を「残り1枠」として表示。0枠の依頼は一覧に出さない。

### 画面⑤ 依頼詳細・受注 `/worker/tasks/[taskId]`

- 依頼内容（`description` 全文）
- **撮影条件** — 箇条書き。`description` をそのまま出すのではなく、AIが抽出した要約があればそれを使う。無ければ全文表示。
- 参考画像のサムネイル横スクロール
- **現地までの距離** — 「1.2 km（約15分）」。徒歩80m/分で概算し、算出方法を注記する。
- 期限・報酬
- **「この依頼を受ける」ボタン**（緑・全幅）
  - `409 TASK_FULL` のときは「他のワーカーが受注済みです」とトースト表示し、一覧へ戻す。
  - 受注成功で画面⑥へ遷移。
- 既に自分が受注済みなら「撮影に進む」ボタンに切り替える。

### 画面⑥ 撮影・アップロード `/worker/tasks/[taskId]/capture`（D-02）

**最重要画面。全画面のカメラビューとする。**

**実装**
```
1. navigator.mediaDevices.getUserMedia({ video: { facingMode: "environment" } })
2. navigator.geolocation.watchPosition() で位置を追跡し続ける
3. シャッター押下の瞬間に:
   - <canvas> へ描画して JPEG(quality 0.9) を生成
   - watchPosition の最新座標と accuracy を取得
   - new Date().toISOString() で撮影時刻を記録
4. 画像＋座標＋時刻＋deviceInfo を multipart で POST /api/submissions
```

**UI要素（草案⑥に準拠）**
- 上部左: 閉じるボタン、上部右: フラッシュ切替（対応端末のみ）
- 左上バッジ: **「GPS取得中」→「GPS取得済」** の状態表示（緑）
- 半透明オーバーレイに **タイムスタンプ**をリアルタイム表示
- 下部の情報バー: 緯度 / 経度 / 時刻 / 端末名を4カラムで表示
- 中央: シャッターボタン（白丸）、右: インカメ/アウトカメ切替
- 撮影後はプレビューに切り替え、「撮影して送信」（緑・全幅）と「撮り直す」を表示

**必須のガード**
- **位置情報の取得に失敗している間はシャッターを無効化**し、「位置情報を有効にしてください」と表示する。位置情報なしの提出を許可しない。
- `getUserMedia` が使えない環境（HTTPS外・非対応ブラウザ）では、ファイル選択によるアップロードにフォールバックする。このときは警告バナーを出し、`deviceInfo.captureMode = "fallback_upload"` を送る。
- 送信中は進捗インジケータを出し、二重送信を防ぐ。

### 画面⑦ AI画像検品・安全処理 `/worker/tasks/[taskId]/status`

提出後に自動遷移。`GET /api/submissions/{id}` を **2秒間隔でポーリング**する。

- チェック4項目を順に表示し、判明したものから ✓ を点灯させる（草案⑦の見た目）:
  **構図確認 / 対象物確認 / 位置・時刻確認 / 顔・ナンバー保護**
- 処理中の項目はスピナー表示。
- 結果パネル:
  - `approved` → 緑「スコア高 → マスク / ブラー処理」＋ 報酬確定の表示、「依頼一覧へ戻る」
  - `rejected` → 赤「スコア低 → 再撮影を依頼」→ 画面⑧の内容を続けて表示

---

### 画面⑧ 再撮影フィードバック（画面⑦内のセクション）

- `issues` を赤いエラー行として列挙する（草案⑧の「対象が写っていません」「暗すぎます」「別アングルで再撮影してください」に対応）。
- **「あと{remaining}回まで再撮影できます」** を明示する。
- 「再撮影する」ボタン → 画面⑥へ戻る。
- `retake.allowed === false`（上限到達）のときはボタンを出さず、「再撮影の上限に達したため、この依頼は他のワーカーへ再開放されました」と表示して一覧へ戻す導線のみにする。
- `aiValidationStatus === "error"` のときは「システム側の問題で検品できませんでした。もう一度送信してください（再撮影回数は消費されません）」と表示する。

### 画面⑨ 結果閲覧 `/client/tasks/[taskId]/results`

- ステータスバッジ「完了」
- **安全処理済み画像**（`processedImageUrl`）を大きく表示。**原本は取得も表示もしない。**
- **AI要約** — `aiSummary`
- 撮影時刻 / 撮影位置 / 信頼度スコア（`realityScore`）の3行
- 「詳細を見る」ボタン → 画面⑩
- N人受注の場合は結果をカードの縦並びにし、**合格した順に随時追加表示**する（D-07）。全員分が揃わなくても表示すること。

---

### 画面⑩ 結果詳細 / レポート `/client/tasks/[taskId]/results/[submissionId]`

- 依頼内容（原文）
- **回答サマリー（AI要約）**
- **画像一覧（安全処理済み）** — サムネイルグリッド。4枚以上は「+N」表示。
- **GPS / タイムスタンプ** — 緯度・経度・時刻を数値で表示
- **Reality Score / 信頼度** — `realityScore` をバッジ表示。タップで内訳（`location_check` の各項目）を展開表示する。
- **ワーカー評価** — 表示名・アバター・星（`trustScore`、5段階）
- 「レポートを印刷」ボタン（`window.print()` 用のプリントスタイルを当てる）は任意実装。

## 5. エラー処理・ローディング

- API失敗時はトーストで日本語メッセージを表示し、`error.code` に応じた文言を `lib/api/errorMessages.ts` に集約する。
- 一覧・詳細の初期ロードはスケルトンUIを表示する。
- ポーリングは**最大60秒**で打ち切り、「処理に時間がかかっています。画面を再読み込みしてください」を表示する（無限ポーリングを防ぐ）。
