# 05. フロントエンド仕様

Next.js 14 (App Router) + TypeScript + Tailwind CSS。
GUI草案の画面①〜⑩に、公開プロフィール（画面⑪）を加えた構成。**画面番号は草案に対応しているため変更しない。**

---

## 1. デザイントークン

`tailwind.config.ts` の `theme.extend` に定義する。**役割ではなく文脈で使い分ける。**

| 用途 | Tailwind クラス | 値 |
|---|---|---|
| 依頼する側の操作 | `client` | `#2563EB`（blue-600） |
| 撮影する側の操作 | `worker` | `#059669`（emerald-600） |
| AI判定・安全処理 | `ai` | `#7C3AED`（violet-600） |
| 合格・成功 | `pass` | `#10B981`（emerald-500） |
| 不合格・再撮影 | `fail` | `#EF4444`（red-500） |
| 警告 | `warn` | `#F59E0B`（amber-500） |
| 本文の最大幅 | `max-w-app` | `28rem` |
| カードの角丸 | `rounded-card` | `1rem` |

背景は `slate-50`、カードは `white` + `border-slate-200` + `rounded-2xl` + `shadow-sm`、
本文は `slate-800`、補助テキストは `slate-500`。

**レイアウト方針**

- **モバイルファースト（基準幅 390px）で作り、PCでは導線の置き方だけを変える。**
  同じコンポーネントを Tailwind の `md:` / `lg:` で出し分け、画面を二重に作らない。

| 要素 | モバイル（〜md） | PC（md〜） |
|---|---|---|
| ナビゲーション | 画面下部の固定タブバー | 左の固定サイドナビ（`w-56` / lg で `w-64`）。下部タブは隠す |
| ヘッダー | ロゴ＋現在のユーザー | 戻るボタンのみ（ロゴとユーザーはサイドナビ） |
| 本文の幅 | `max-w-app`（28rem） | `md:max-w-5xl`。縦に読む画面は `md:max-w-2xl` で絞る |
| 投稿一覧 | 2列 | `md:` 3列 / `lg:` 4列（地図画面は地図と並べるため2列） |
| 地図 | `h-72`（ピッカーは `h-56`） | `md:h-96`（ピッカーは `md:h-72`） |
| 地図でさがす | 地図の下に一覧 | `lg:` 左に地図（追従）・右に一覧 |
| 依頼詳細 | 画像の下に内容 | `lg:` 左に画像（追従）・右に内容 |
| 撮影画面 | 全画面カメラ | 端末幅相当（`md:max-w-app`）で中央寄せ |
| ログイン・新規登録 | 上寄せ | 縦方向も中央寄せ |

- ログイン後は**全ユーザーが同じ画面構成**を使う（クライアント／ワーカーで画面を分けない）。
- 画面下部の固定タブバー: **ホーム / いいね / 依頼する（中央の目立つ丸ボタン）/ お知らせ / マイページ**。
  お知らせタブには**未読件数のバッジ**を出す（30秒間隔で `GET /api/notifications/unread-count`）。
- 撮影画面（画面⑥）ではシェルを外して全画面にする。ログイン・新規登録画面ではナビを出さない。
- タブの着地点（`/home` `/likes` `/requests/new` `/notifications` `/me`）では戻るボタンを出さない。
- 投稿（依頼）は**正方形サムネイルのカード**をグリッドで並べる。カードの仕様は6節。
- ステータスは `StatusBadge` / `AssignmentBadge` / `ValidationBadge` で統一表示する。
- 上部ヘッダー右のマイページ導線は、丸型アイコン（`Avatar`）＋表示名で表す。
- **0〜100 のスコアは数値の行ではなくゲージで見せる**（`TrustGauge` / `TrustBar`）。
  80以上は緑（pass）、50以上は橙（warn）、50未満は赤（fail）、未算出は灰。

| task status | ラベル | 色 |
|---|---|---|
| screening | 審査中 | amber |
| needs_info | 情報補足待ち | amber |
| rejected | 却下 | red |
| open | 募集中 | blue |
| in_progress | 進行中 | blue |
| completed | 完了 | emerald |
| expired | 期限切れ | slate |
| cancelled | 取消済み | slate |

## 2. 認証と画面遷移（D-06）

### ログイン `/login` / 新規登録 `/signup`

- ログインIDとパスワードを入力する。新規登録は ログインID / パスワード / 表示名 の3項目。
- 入力制約はバックエンド（`app/schemas/auth.py`）と揃える。
  ログインIDは半角英数字とアンダースコア3〜32文字、パスワードは8文字以上。
- 成功したらトークンとユーザー情報を `localStorage` に保存し（`lib/session.ts`）、
  `lib/api/client.ts` が全リクエストに `Authorization: Bearer` を自動付与する。
- 有効期間は既定30日。アプリを閉じてもログイン状態が続く。
- セッションの変更は `CustomEvent` と `storage` イベントで購読する（`subscribeSession()`）。
  ヘッダーのアイコンとガードが同時に更新される。

### 着地点とガード

- ルート `/` はログイン状態を見て `/home`（ログイン済み）か `/login` へ振り分ける。
- **ログイン後は全員が同じホーム `/home`（近くの撮影依頼一覧）に着地する。**
  そこから下部タブで「依頼する」「マイページ」へ移動する。
- `components/auth/AuthGuard.tsx` が未ログインを `/login` へ送り、`GET /api/auth/me` で
  トークンの有効性を確認する。401 を受けたらセッションを破棄してログイン画面へ戻す
  （通信不能では締め出さない）。`apiFetch` も 401 を受けた時点でセッションを捨てる。
- ログアウトはマイページから行う。

### ルート一覧

| パス | 内容 | 画面番号 |
|---|---|---|
| `/login` `/signup` | ログイン / 新規登録 | |

> `/requests` と `/jobs` はタブではなくマイページから入る
> （メルカリの「出品した商品 / 購入した商品」と同じ位置づけ）。

### タブ移動時のちらつき防止（`lib/pageCache.ts`）

タブを行き来するたびに白紙→スケルトン→内容と切り替わるのを避けるため、
**直前の表示内容をメモリに保持する**。API の再取得は通常どおり行い、その待ち時間だけ前回の内容を出す。

- キーはユーザーIDでスコープする（アカウントを切り替えたら他人の内容が出ない）。
- ブラウザを更新すると破棄される。**永続キャッシュではない。**
- 対象: ホーム / いいね / お知らせ / マイページ。

### プロフィール（マイページ上部）

- 丸型アイコン（`Avatar`）をタップするとファイル選択が開き、選んだ画像を
  `POST /api/users/me/avatar` へ送ってその場で差し替える。「削除」で既定へ戻せる。
- 更新後のユーザー情報は `saveUser()` でセッションへ書き戻し、ヘッダーのアイコンも同時に変わる。
- 信頼度スコアは数値の行ではなく `TrustGauge`（最大値100）で見せる。
- **受け取った評価**（`GET /api/users/me/reviews`）を平均星と件数で表示し、
  タップでモーダルを開いて個別の評価（星・タグ・コメント）を一覧する。**評価者は表示しない。**

## 3. 画面仕様

### 画面① 依頼作成 `/requests/new`

**構成（上から）**

0. **過去の依頼から再投稿** — 自分が出した依頼の一覧（`/requests`）へ移動し、
   日時だけ変更して再投稿できる導線を表示する。
1. **撮影地点を指定** — 3つの方法をすべて用意する。地図だけでは「どこにピンを置けばよいか」が
   分かりにくいため、実景でも確認できるようにしている。
   - **地名・住所で検索**（`components/map/PlaceSearchBox.tsx`）— 選んだ地点へ地図とピンを移動する
   - **地図をタップ** — ピンを置き、逆ジオコーディングで住所を補完する
   - **ストリートビュー**（`components/map/StreetViewPanel.tsx`）— 「地図 / ストリートビュー」のタブで切り替える。
     周囲をドラッグで見回し、矢印で移動できる。「この位置を撮影地点にする」でその位置をピンにする
   - 初期中心は環境変数の既定座標。地図の要素は非表示中も破棄しない（Google Maps は要素を再利用するため）
   - キーの認証に失敗した場合（課金未有効・API未有効・リファラー制限違反）は `window.gm_authFailure` で
     検知し、**Googleの灰色オーバーレイではなく日本語の対処案内＋緯度経度の手入力**へ切り替える
2. **日時を指定** — 撮影希望日時（`scheduledAt`）と提出期限（`deadlineAt`）。日付＋時刻ピッカー。
3. **撮影人数** — 1〜10のステッパー。
4. **報酬** — 円単位の数値入力。100〜100000。
5. **受注条件（任意）** — `minWorkerRating`（1.0〜5.0）。未指定なら誰でも受注できる。
   **評価が1件も無いワーカーは足切りされない**旨を注記する。
6. **詳細メッセージ入力** — textarea。10〜1000文字、文字数カウンタ付き。
   - タイトル入力後に「AIで詳細を作成」を押すと、60〜120文字程度の短い詳細文を生成する
     （`POST /api/tasks/generate-description`）。生成後も自由に編集できる。
7. **よくある依頼のクイック入力** — タイトルと詳細メッセージのそれぞれの上に、単語のチップを並べる
   （`components/task/PresetChips.tsx` / ひな形は `lib/taskPresets.ts` に11件）。
   - タイトル側をタップ → タイトルを入れ、**詳細が空のときは詳細もまとめて入れる**
   - 詳細側をタップ → 詳細だけを置き換える
   - いま入っている文章と一致するチップは選択済み表示にし、**もう一度タップすると欄を空にする**
     （タイトル側の取り消しでは、まとめて入れた詳細も手で書き換えていなければ一緒に消す）
   - ひな形の文章は**AI審査（機能A）を通る具体性**を持たせる。「何が写っていれば確認できたと
     言えるか」を必ず1文に含め、個人の監視と読み替えられる表現は避ける
8. **参考画像アップロード** — 最大3枚。サムネイル＋「＋」ボタン。
9. **「依頼内容を確認」ボタン** — 全幅の青ボタン。

**バリデーション（送信前）**
- 未入力項目があればボタンを無効化し、該当フィールド下に赤字でメッセージ表示。
- 送信中はボタンをローディング状態にする。**AI審査が同期実行されるため時間がかかる旨**を
  「AIが依頼内容を審査しています…」というテキストで表示する。
  実測 20〜90秒だったため、文言は「30秒〜1分ほど」としている。

作成結果は `lib/reviewHandoff.ts` が `sessionStorage` に置き、画面②が読み出す。

### 画面② AIリクエスト審査 `/requests/new/review`

`POST /api/tasks` のレスポンスを受けて表示する。
**クエリ `?taskId=` が付いている場合は `GET /api/tasks/{id}/review` で取り直す**
（お知らせから開き直したとき用）。

**構成**
- ヘッダー:「AIリクエスト審査（OrcaAI）」
- **スコアリング** — `reviewScore` を `TrustGauge`（リング状のゲージ・最大値100）で表示する。
- **チェック項目4行** — 内容の妥当性チェック / リスクチェック / 重複・類似チェック（＋スコアリング）。
  各行の右に ✓（emerald）または ✗（red）アイコン。
- 結果パネル（`decision` により分岐）:

| decision | 表示 |
|---|---|
| `approved` | 緑パネル「スコア高 → 依頼を公開」。3秒後に画面③へ自動遷移（「今すぐ確認」ボタンも置く） |
| `needs_info` | 赤パネル「スコア低 → 内容補足を依頼」。`missingInfo` を箇条書き表示し、**その場で詳細メッセージを編集できるtextareaと「再審査する」ボタン**を出す（`POST /api/tasks/{id}/resubmit`） |
| `rejected` | 赤パネル。`rejectionReason` を表示。編集フォームは出さず、「新しい依頼を作成」ボタンのみ |

> `rejected` のときに再提出フォームを出さないのは、**却下された依頼の言い換えによる回避を促さないため**。
> APIも `needs_info` からしか再審査を受け付けない。

### 画面③ 依頼公開・進行状況 `/requests/[taskId]`

**構成**
- ステータスバッジ（例:「募集中」）
- **依頼内容の要約** — `reviewSummary`
- **撮影してもらう時間帯** — `TimeWindow`（`scheduledAt`〜`deadlineAt` を幅として図で示す）。
  撮影は分単位で狙って行けるものではないため、**一点の日時ではなく幅**で伝える
- 位置情報 / 報酬 / 募集人数（アイコン付きの行）
- **進行状況タイムライン** — `timeline` 配列を縦のステッパーで表示。
  `done` は青丸＋日時、`current` は青枠、`pending` は灰丸。
- N人受注時は「受注状況 2 / 3人」を表示する。
- `completed` または合格提出が1件以上あるとき、「結果を見る」ボタン（→画面⑨）を表示する。
- **10秒ごとにポーリング**してタイムラインを更新する。
- `open` / `in_progress` の間は、**現在より後の提出期限へ延長**できる
  （`POST /api/tasks/{id}/extend-deadline`）。
- 取消可能な状態のときだけ「依頼を取消」を出す（受注済みは不可）。

`/requests`（依頼一覧）では、各依頼の「この依頼を複製」から撮影希望日時と提出期限だけを
変更して再投稿できる。場所・報酬・人数・依頼内容・参考画像を引き継ぎ、新しい依頼として
再びAI審査を行う。過去の依頼を保存済みテンプレートとして扱う。

### 画面④ 依頼一覧 `/home` / 地図 `/search`

もとの「地図／リスト」のタブ切替を、**ホーム（リスト）** と **地図でさがす** の2画面に分けた。

- どちらも起動時に `navigator.geolocation.getCurrentPosition()` で現在地を取得し、
  `GET /api/tasks/nearby` を呼ぶ。位置情報が拒否された場合は既定座標にフォールバックし、
  ホームでは「現在地を取得できませんでした」を表示する。
- **ホーム `/home`** — 上部に**地名・住所の検索ボックス**、検索範囲（1 / 3 / 5 / 10 / 30km）、
  並び替え（距離順 / 報酬順 / 期限順）、「♡ 条件を保存」を置く。その下に投稿カードをグリッドで並べる。
  「地図で見る」から `/search` へ移動する。
- **地図でさがす `/search`** — 現在地を青丸、タスクを緑ピンで表示。ピンをタップすると下部にカード
  （タイトル・報酬・距離・期限・「詳細を見る」）を表示。検索・範囲・並び替え・条件保存はホームと同じ。
  クエリ `lat` / `lng` / `radiusKm` / `sort` で初期状態を指定できる（保存した検索条件から開くため）。
- 各カードに `remainingSlots` を「残り1枠」として表示。**0枠の依頼はAPIが返さない。**
- **自分が出した依頼は表示されない**（受注できないため、APIが除外する）。

### 画面⑤ 依頼詳細・受注 `/jobs/[taskId]`

投稿カードをタップするとここへ来る（依頼主が入力した内容を一通り表示する）。

- サムネイル（左上に `CornerBadge`、右上にハート）
- **現地の様子（ストリートビュー）** — 受注前に現場を実景で確認できる。取得できない地点では理由を表示する
- 依頼内容（`description` 全文）
- **撮影条件** — AIが抽出した要約（`reviewSummary`）があればそれを使う。無ければ全文表示。
- **依頼者** — アバター・表示名・「完了率 75%・依頼12件」の要約を1行で出し、
  タップで画面⑪（公開プロフィール）へ遷移する。実績が無い場合は「依頼実績なし」と表示。
  クライアントは画面⑩でワーカーを評価できるので、**その逆方向を用意して非対称を解消する**のが目的。
- **撮影してほしい時間帯** — `TimeWindow`（残り時間つき）
- 参考画像のサムネイル横スクロール
- **現地までの距離** — 「1.2 km（徒歩約15分）」。徒歩80m/分で概算し、算出方法を注記する。
- 報酬・残り枠・受注条件（`minWorkerRating` があれば明示する）
- **「この依頼を受ける」ボタン**（緑・全幅）
  - `409 TASK_FULL` のときは「他のワーカーが受注済みです」とトースト表示し、一覧へ戻す。
  - `403 RATING_REQUIREMENT_NOT_MET` のときは条件を満たしていない旨を出す。
  - 受注成功で画面⑥へ遷移。
- 既に自分が受注済みなら「撮影に進む」ボタンに切り替える。
- **撮影提出前は「受注を辞退する」を表示する。** 確認後に辞退し、占有していた募集枠を即座に戻す
  （提出後は出さない）。

### 画面⑥ 撮影・アップロード `/jobs/[taskId]/capture`（D-02）

**最重要画面。全画面のカメラビューとする**（`AppShell` はこの画面でシェルを外す）。

**実装**
```
1. navigator.mediaDevices.getUserMedia({ video: { facingMode: "environment" } })
2. navigator.geolocation.watchPosition() で位置を追跡し続ける
3. シャッター押下の瞬間に:
   - <canvas> へ描画して JPEG(quality 0.9) を生成
   - watchPosition の最新座標と accuracy を取得
   - new Date().toISOString() で撮影時刻を記録
4. 画像＋座標＋時刻＋deviceInfo を multipart で POST /api/submissions
5. 202 が返ったら /jobs/[taskId]/status?submissionId=... へ遷移
```

**UI要素**
- 上部左: 閉じるボタン、上部右: フラッシュ切替（対応端末のみ）
- 左上バッジ: **「GPS取得中」→「GPS取得済」** の状態表示（緑）
- 半透明オーバーレイに **タイムスタンプ**をリアルタイム表示（`MetadataOverlay`）
- 下部の情報バー: 緯度 / 経度 / 時刻 / 端末名を4カラムで表示
- 中央: シャッターボタン（白丸）、右: インカメ/アウトカメ切替
- 撮影後はプレビューに切り替え、「撮影して送信」（緑・全幅）と「撮り直す」を表示
- 再撮影で来た場合は、前回の `issues` を上部に表示する

**必須のガード**
- **位置情報の取得に失敗している間はシャッターを無効化**し、「位置情報を有効にしてください」と表示する。
  位置情報なしの提出を許可しない。
- `getUserMedia` が使えない環境（HTTPS外・非対応ブラウザ）では、ファイル選択によるアップロードに
  フォールバックする。このときは警告バナーを出し、`deviceInfo.captureMode = "fallback_upload"` を送る。
- 送信中は進捗インジケータを出し、二重送信を防ぐ。
- **撮影から送信まで10分（`CAPTURE_FRESHNESS_SECONDS`）を超えると `400` になる。**

### 画面⑦ AI画像検品・安全処理 `/jobs/[taskId]/status`

提出後に自動遷移。`GET /api/submissions/{id}` を**段階的バックオフでポーリング**する
（`lib/polling.ts`）。検品は実測30秒〜15分かかるため、一律の間隔では成立しない。

| 経過時間 | 次の間隔 |
|---|---|
| 〜30秒 | 2秒（スタブモードならここで終わる） |
| 30秒〜1分30秒 | 5秒 |
| 1分30秒〜5分 | 15秒 |
| 5分〜 | 30秒 |

- 打ち切りは**15分**（`MAX_POLL_MS`）。15分をカバーしても総リクエストは62回に収まる
- `error` も終了状態として扱い、待ち続けない（再送信の案内を出す）
- **タブを離れている間はブラウザが `setTimeout` を抑制する**ため、`visibilitychange` で
  復帰時に即座に1回取得する
- 待機中は経過時間（`formatElapsed()`）と「30秒〜15分ほどかかる」目安を表示する
- 打ち切り後は「もう一度確認する」と「受注した依頼へ」の導線を出す

**表示**
- チェック4項目を順に表示し、判明したものから ✓ を点灯させる:
  **構図確認 / 対象物確認 / 位置・時刻確認 / 顔・ナンバー保護**
  （対応するキーは `docs/03-api.md` 3.7 の表）
- 処理中の項目はスピナー表示。
- 結果パネル:
  - `approved` → 緑「スコア高 → マスク / ブラー処理」＋ 報酬確定の表示、加工済み画像、「依頼一覧へ戻る」
  - `rejected` → 赤「スコア低 → 再撮影を依頼」→ 画面⑧の内容を続けて表示
- 依頼者から評価が付いていれば（`workerReview`）、星とタグを表示する。

### 画面⑨ 結果閲覧 `/requests/[taskId]/results`

### 画面⑩ 結果詳細 / レポート `/requests/[taskId]/results/[submissionId]`

- 依頼内容（原文）
- **回答サマリー（AI要約）**
- **画像（安全処理済み）**
- **GPS / タイムスタンプ** — 緯度・経度・時刻を数値で表示
- **Reality Score / 信頼度** — `realityScore` を `TrustBar` で表示。

- 「レポートを印刷」ボタン（`window.print()` 用のプリントスタイル）は任意実装。

### 画面⑪ 公開プロフィール `/users/[userId]`（閲覧専用）

草案①〜⑩には無い追加画面。画面⑤の依頼者行から遷移する。

- **ロールに依存しない。** 1アカウントが依頼者とワーカーの両面を持ちうるため、URLは
  `/users/[userId]` の1本にし、両方の実績を表示する
- ヘッダー: アバター / 表示名 / 「2026年8月から利用」
- **依頼者としての実績**: 公開した依頼数 / 完了した依頼数 / 完了率
- **ワーカーとしての実績**: 信頼度スコア（`TrustGauge` で 0〜100 を表示）/ 合格した提出数 /
  平均評価（星）と件数
- 実績が0の側もセクションを出し、「まだ依頼の実績がありません」等の空状態を表示する
- **編集機能は持たない。** 編集は各自のマイページで行う
- 末尾に「このページは閲覧専用です。連絡先などの個人情報は表示されません。」と明記する

公開してよい情報の範囲は `docs/03-api.md` 3.4.1 に従う。**平均報酬・却下された依頼は出さない。**

### お知らせ `/notifications`

- `GET /api/notifications` を**10秒ごとにポーリング**する。
- 種類ごとに絵文字アイコンを出し、未読は青系の背景＋ドットで示す。
- タップすると**その内容を確認・操作できる画面**へ遷移する。既読化は遷移を待たせず裏で行う。

| type | 遷移先 |
|---|---|
| `task_needs_info` / `task_rejected` | `/requests/new/review?taskId=…`（画面②を開き直す） |
| `task_completed` | `/requests/{taskId}/results` |
| `submission_approved` / `submission_retake` / `submission_failed` | `/jobs/{taskId}/status?submissionId=…`（IDが無い古いデータは `/jobs/{taskId}`） |
| その他 | `/requests/{taskId}` |

- 未読が1件以上あるとき「すべて既読にする」を出す（`POST /api/notifications/read-all`）。
- 10件ごとにページ送りする。件数が減ってページが消えたら自動で戻す。

## 5. データ取得とエラー処理

- API呼び出しは `src/lib/api/` のクライアント関数に集約する。**コンポーネントから `fetch` を直接書かない。**
- `apiFetch()` が `Authorization` の付与・エラー形式の解釈・401時のセッション破棄をまとめて行う。
- **GET / HEAD の通信例外だけ1回再試行する**（600ms後）。POST / DELETE は再試行しない
  （二重受注・二重依頼という実害が出るため）。
  Cloud Run のコールドスタートとモバイル回線の一瞬の切断がこれで吸収できる。
- API失敗時はトーストで日本語メッセージを表示し、`error.code` に応じた文言を
  `lib/api/errorMessages.ts` に集約する。
- 一覧・詳細の初期ロードはスケルトンUI（`Skeleton`）を表示する。
- ポーリングは**最大15分**で打ち切り、結果を後から確認できる導線（「受注した依頼へ」）を出す。
  間隔は段階的バックオフ（画面⑦参照）。無限ポーリングはしない。
- 相対URL（`/api/files/...` `/api/users/.../avatar`）は `resolveApiUrl()` でバックエンドを指す
  絶対URLへ変換してから `<img>` に渡す。

## 6. 投稿カード（`components/task/TaskCard.tsx`）

一覧（ホーム・地図でさがす・いいね）で共通に使う。メルカリの商品カードに相当する。

| 位置 | 内容 |
|---|---|
| 全面 | **正方形のサムネイル**（`thumbnailUrl`）。`aspect-square` ＋ `object-cover` |
| 左上 | タグ。**角を切り取る三角形**の中に白文字（`CornerBadge`）。`badges` の先頭1つだけ |
| 右上 | ハート（いいね）。自分の依頼（`isMine`）では出さない |
| 左下 | 報酬（`¥2,500`） |
| 下部 | タイトル（2行まで）、距離・残り時間・残り枠 |

- カード全体がリンクで、タップすると `/jobs/{taskId}`（依頼主が入力した詳細）へ移動する。
- ハートのタップはカードの遷移を止める（`preventDefault` ＋ `stopPropagation`）。
- サムネイル未生成のあいだは「画像を準備しています…」を出す（生成は依頼公開後に背景で走る）。

**タグの意味**（判定はサーバー側。`app/services/task_card.py`）

`badges` は**優先順位の高い順**に並ぶ。角は1つしか使えないため、カードは先頭だけを描く。

| 優先 | badge | 表示 | 条件 |
|---|---|---|---|
| 1 | `sold` | SOLD（濃いグレー） | 取引終了（`status = completed`） |
| 2 | `hot` | HOT（赤） | 詳細の閲覧数が20以上（`HOT_VIEW_COUNT`） |
| 3 | `new` | NEW（緑） | 作成から24時間以内（`NEW_TASK_HOURS`）。**SOLD のときは付けない** |

三角形は CSS の border で作る（`border-top` を塗り `border-right` を透明にすると左上の直角三角形になる）。
文字は `-rotate-45` で斜辺と平行に置き、三角形の重心へ寄せる。詳細画面は `size="lg"` で同じ意匠を使う。

**サムネイルの由来**（`thumbnailSource`）

| 値 | 内容 |
|---|---|
| `reference` | 依頼と一緒にアップロードされた参考画像の1枚目 |
| `generated` | ストリートビューを元にAIが生成した画像 |
| `streetview` | ストリートビュー画像をそのまま正方形に切り抜いたもの |
| `placeholder` | 外部APIが使えないときにサーバーが描いた画像（地点ピン＋タイトル＋住所） |

サムネイルの意匠を変えたときは `python -m scripts.regenerate_thumbnails --force` で作り直す。
