# 06. 実装フェーズ

**方針: デモ優先（D-10）。** 画面フローを最初に一気通貫で通し、その後にAI機能を実際のものへ差し替える。
各フェーズの完了条件をすべて満たしてから次へ進み、フェーズごとにコミットすること。

```
Phase 0  環境構築
Phase 1  DB＋CRUD API（AIはスタブ）
Phase 2  画面①〜⑩の一気通貫（★ここでデモが成立する）
Phase 3  依頼審査AIの実装
Phase 4  画像検品AI＋位置偽装対策の実装
Phase 5  プライバシー自動マスキングの実装
Phase 6  仕上げ（期限ジョブ・決済スタブ・エラー処理）
```

---

## Phase 0 — 環境構築

**作業**
1. `frontend/` に Next.js 14 (App Router, TypeScript, Tailwind, ESLint) を初期化。
2. `backend/` に FastAPI プロジェクトを作成（`pyproject.toml`、依存: fastapi, uvicorn, sqlalchemy, alembic, psycopg, pydantic-settings, httpx, pillow, python-multipart, apscheduler）。
3. `docs/01-architecture.md` のディレクトリ構造を作成。
4. `.env.example` / `.env.local.example` を配置。
5. Supabase プロジェクトへ接続、Storage に2バケット作成（`submissions-raw` は非公開、`submissions-processed` も非公開＋署名URL配信）。
6. CORS設定、`GET /api/health` の疎通確認。

**完了条件**
- [ ] `npm run dev` と `uvicorn` が同時に起動する
- [ ] フロントから `/api/health` を叩いて 200 が返る
- [ ] `.env` 未設定でもアプリが起動し、不足している変数を起動ログで警告する

---

## Phase 1 — DB＋CRUD API（AIはスタブ）

**作業**
1. `docs/02-database.md` のENUM・全テーブルを Alembic マイグレーションで作成。
2. SQLAlchemyモデル、Pydanticスキーマ、リポジトリ層を実装。
3. `scripts/seed_demo_users.py` でデモユーザー4名を投入。
4. ログインID＋パスワードによる認証（`/api/auth/*`）と、トークンからのユーザー解決（`deps.py`）を実装。
5. `docs/03-api.md` の全エンドポイントを実装。**ただしAI処理は `OrcaClient` のスタブモードを使う。**
6. ステータス遷移ロジック、受注時の `SELECT FOR UPDATE`、再撮影ループのカウントを実装。
7. 画像アップロードとStorage保存、署名URL発行を実装。

**完了条件**
- [ ] `alembic upgrade head` が成功し、全テーブルが作成される
- [ ] 依頼作成 → 受注 → 提出 → 検品(スタブ) → 合格 までを curl だけで実行できる
- [ ] 再撮影ループが仕様通り動く（1回目不合格 → 2回目合格 / 3回不合格で `failed` と枠再開放）
- [ ] 受注枠を超えた `accept` が `409 TASK_FULL` を返す
- [ ] pytest で状態遷移のテストが通る（最低: 受注競合、再撮影上限、期限超過）

---

## Phase 2 — 画面①〜⑩の一気通貫 ★デモ成立点

**作業**
1. デザイントークン設定、共通UIコンポーネント作成。
2. ログイン・新規登録画面と、`Authorization: Bearer` の自動付与（`lib/session.ts` / `lib/api/client.ts`）。
3. 画面①〜⑩をすべて実装（`docs/05-frontend.md`）。
4. Google Maps 連携（地点ピッカー、近傍タスクのマーカー表示、地名・住所での検索）。
5. **画面⑥のカメラ実装**（`getUserMedia` ＋ `watchPosition`、メタデータ同時送信）。
6. ポーリングによる検品状況の更新。

**完了条件**
- [ ] クライアントで依頼作成 → ワーカーに切替えて受注・撮影 → 検品結果表示 → クライアントで結果閲覧、までをブラウザ操作のみで完走できる
- [ ] 画面⑥で位置情報が取れないときシャッターが押せない
- [ ] 再撮影ループが画面上で確認できる（スタブが奇数回目を落とすため必ず1回発生する）
- [ ] スマートフォンの実機（HTTPS経由）でカメラとGPSが動作する

> **このフェーズ終了時点で、AI部分がスタブのままでもデモが成立する状態にすること。**
> 以降のフェーズは、スタブを本物に置き換える作業である。

## Phase 3 — 依頼審査AIの実装

**作業**
1. `OrcaClient` の実HTTP実装（`docs/04-ai-pipeline.md` 1節）。
   - **OrcaRouterの仕様が未確定の場合はここで作業を止め、人間に確認すること。**
2. `task_review.py` にプロンプトと判定ロジックを実装。
3. `ai_invocations` へのログ記録。
4. 参考画像がある場合の `tier="vision"` への切替。

**完了条件**
- [ ] 正常な依頼が `approved` になり公開される
- [ ] 情報不足の依頼（例:「写真撮ってきて」だけ）が `needs_info` になり、`missingInfo` に具体的な補足要求が入る
- [ ] 危険な依頼（例:「隣人が在宅か確認したい」「この家の施錠状況を見てきて」）が `rejected` になる
- [ ] `needs_info` から補足して再審査すると `approved` に変わる
- [ ] `ORCA_STUB_MODE=true` に戻すとスタブで動作する

---

## Phase 4 — 画像検品AI＋位置偽装対策

**作業**
1. `location_check.py` の決定論的チェック C-1〜C-4, C-6 を実装。
2. `image_validation.py` のVLM検品を実装。
3. C-5（環境整合）と `reality_score` の算出を実装。
4. `submission_pipeline.py` で統括処理を組み立て、トランザクション境界を確定させる。
5. EXIF抽出（Pillow）を実装。

**完了条件**
- [ ] 依頼内容に合った画像が合格し、無関係な画像が `SUBJECT_MISSING` で不合格になる
- [ ] 暗い画像・ブレた画像が該当コードで不合格になる
- [ ] 依頼地点から200m以上離れた座標で提出すると `LOCATION_MISMATCH` で不合格になる
- [ ] `capturedAt` を10分以上前に偽装すると弾かれる
- [ ] AI呼び出しを意図的に失敗させると `error` になり、**再撮影回数が消費されない**
- [ ] `reality_score` が減点ルール通りに算出される

## Phase 5 — プライバシー自動マスキング

**作業**
1. Ultralytics YOLO を導入し、重みを `models_weights/` へ配置（`.gitignore` に追加）。
2. 顔検出＋ぼかしを実装。
3. 車両検出 → VLMへナンバープレート座標を問い合わせ → 黒塗り（採用案A）。
4. 表札・番地のVLM座標問い合わせ → ぼかし。
5. 加工後画像を `submissions-processed` へ保存し、`masking_result` を記録。

**完了条件**
- [ ] 通行人の顔がぼかされ、人物の全身はぼかされていない
- [ ] ナンバープレートが黒塗りされる
- [ ] 重みファイルが無い環境でも例外を出さずスキップし、ログに警告が出る
- [ ] クライアント向けAPIのレスポンスに原本URLが一切含まれない（テストで検証すること）
- [ ] 画面⑩でマスキング済み画像のみが表示される

---

## Phase 6 — 仕上げ

**作業**
1. `expire_tasks.py` の実装とAPSchedulerへの登録（5分間隔＋起動時1回）。
2. 決済スタブ（`payment_stub.py`）— 合格時に `charge` / `payout` を記録。UIに「報酬が確定しました」等の表示を追加。
3. エラーメッセージの日本語化と統一、トースト実装。
4. ローディング・スケルトンUI、ポーリングの60秒打ち切り。
5. `README.md` にセットアップ手順とデモシナリオを記載。

**完了条件**
- [ ] 期限切れタスクが自動で `expired` になり、ワーカー側の一覧から消える
- [ ] 合格済み提出がある状態で期限が切れた場合は `completed` になる
- [ ] `payments` に charge / payout が1件ずつ記録される
- [ ] 主要なエラーがすべて日本語で表示される

---

## デモシナリオ（Phase 6完了時に通すこと）

1. クライアントで「駅前の再開発工事の進捗確認」を作成 → **AI審査で85点、公開される**
2. 参考に「隣の家に人がいるか確認してほしい」を作成 → **AIが却下する**（安全性のアピール）
3. 情報不足の依頼を作成 → **AIが補足要求を出す** → 補足して公開
4. ワーカーに切替 → 地図で依頼を発見 → 受注
5. カメラで撮影（GPS・タイムスタンプが画面に出ている状態）→ 提出
6. **1回目は不合格 → 再撮影指示が具体的に表示される** → 再撮影して合格
7. **顔とナンバープレートがマスクされた画像**が生成される
8. クライアントに切替 → 結果画面でAI要約・Reality Score・ワーカー評価を確認
